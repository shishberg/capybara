# Capybara

A split keyboard that grew out of [Rosebear](https://github.com/shishberg/rosebear), whose v4 it was. Earlier versions and their design notes stay in that repo. [`seed/`](seed/README.md) holds the part of Rosebear's v3 generator that the paused board pipeline still runs.

[Design status](docs/design-status.md) lists the current decisions and open questions. It takes precedence over any other doc that disagrees with it.

## Current construction: key tiles

All 36 keys use bought 1U RGB key tiles, hand-wired per half to a [Pro Micro](docs/pro-micro.md) (nRF52840) in that half, the two halves joined by a TRRS cable. The first prototype needs no custom PCBs.

## Browser chassis editor

The keyboard's key layout is **Swung in**, the layout the printed frame uses and the editor's default. It is the only layout kept: the earlier ones were removed on 19 Oct 2026 and stay in git history (509dbd1 is the last commit with them).

Run `make editor` and open **http://127.0.0.1:5177**. The editor builds the Capybara frame for the right hand from the key layout, with the tiles hanging from their switches under the key plates and the Pro Micro, its TRRS jack and its reset switch on the bottom section. The [editor guide](editor/README.md) covers the layout parameters and handles, autosave, project files and the clearance checks, and [editor chassis and wiring](docs/editor-chassis.md) how the case is built and wired. The Pro Micro's, the jack's and the switch's sizes are provisional until measured (see [Pro Micro](docs/pro-micro.md)).

## Hand model

[`hand/`](hand/README.md) holds a measured model of the hand, in the editor's layout axes: fingertip rest positions, thumb landing points, segment lengths and the resting pose. Swung in was laid out from it in the editor's dev-only `?hand` mode, which shows the hand on the keys and checks its reach and the board's height: see the [hand prototype](docs/hand-prototype.md).

## Firmware

[`firmware/`](firmware/README.md) is RMK firmware for the [Pro Micro](docs/pro-micro.md): one nRF52840 board per hand, the hands joined by a TRRS serial link. `make firmware` builds the two UF2s into `output/firmware/`.

## Paused: the pod

Before the Pro Micro, each hand ran a 24-way FFC ribbon to a pod carrying a WT9932P4-TINY (ESP32-P4). [Key PCB quote options](docs/key-pcb-quote-options.md) covers its ribbon pinout and wiring, and the custom breakout and pod boards for it (generated by `tools/build_key_quotes.py` into `output/key-quotes/`). They are kept as reference.

## Paused: seeded flex and flat-thumb boards

The rest of this README describes the `make build` pipeline: flex finger boards, flat rigid thumb PCBs and the LED-free pod. The key tiles replace these boards for the first prototype. The pipeline, its tests and its docs are kept as reference and still build.

Each hand has one 1.6 mm rigid three-key thumb PCB, with fanned outer keys and four wire pads between the home and far keys. All thumb switches share one plane. `flat_thumb.json` controls spacing, fan angles and the whole cluster pose; both PCB and switch-seat geometry use it. See [flat thumb construction](docs/flat-thumb-construction.md) for wiring and printable fit parts.

Finger bending was an unresolved prototype gate when this work paused. A routed transverse coupon, printable combined-motion jig and beam-mode screen exist: [finger bending revision](docs/finger-bend-coupon.md). The full finger files still use the legacy bridges and are not mechanically released.

## Build

Prerequisites: BAML CLI (`baml`), KiCad 10 with its matching `pcbnew` Python and wxPython. `./run` defaults to the macOS KiCad installation; override `KICAD_PYTHON`, `KICAD_ROOT` and `KICAD_CLI` for another installation. Install the isolated geometry dependencies once with `python3 tools/setup_geometry.py`. Ordinary cached builds then need no Java or network access.

```sh
make build
make test
# Fast rebuild: rejects stale geometry instead of silently reusing it.
./run --reuse-geometry
# Export a changed neighboring chassis configuration first:
python3 tools/export_chassis.py ../dactyl-keyboard
```

Supported mechanical configuration: standard five-column, three-row MINIDOX. Change `config.json` and export the chassis again when altering its geometry. The export includes source hashes and the upstream placement functions used to calculate key frames. It does not import the adjacent project's CAD runtime or modify that project.

Outputs:

| Artifact | Purpose |
|---|---|
| `output/seeded/all.kicad_pcb` | Combined labeled overview, grouped by board; rebuilt after a successful full build |
| `output/seeded/*.kicad_pcb` (excluding `all`) | Five native routed boards: two fingers, two flat thumbs, pod |
| `output/seeded/report-all.json` | Metrics, DRC results, explicitly accepted legacy warnings, bend checks |
| `output/electrical-contract.json` | Cross-board wire assignments and diode polarity checks |
| `output/assembly.json` | Individual key frames, nominal collision checks, wiring graph |
| `output/mechanical/flat-thumb/` | Watertight switch-plate and PCB alignment spacer STL files |
| `output/fabrication/thumb_l/`, `thumb_r/` | Flat cluster layout, BOM and Gerber/drill files |
| `output/assembly.scad` | Rigid-island preview and PCB seating relief subtraction modules |
| `output/chassis-right.scad` | New thumb fit assembly preview; not a finished chassis |
| `output/wiring.md` | Assembly connections |
| `output/pod-pins.json`, `pinout.txt`, `firmware-pinout.json` | Pod pin map read back from the built pod: every header pin, its net and why (routed, fixed, reserved, unused) |

The combined overview keeps each board’s nets separate and prefixes component references with the board name. It is a flat review layout, not a fabrication panel or a 3D assembly. Manufacture the individual files; use `wiring.md` for inter-board connections. A single-board build updates only that board; run the full build to refresh `all`.

Open `chassis-right.scad` in OpenSCAD to review the new thumb fit assembly. The STL fit parts are already rendered under `mechanical/flat-thumb/`; they do not require OpenSCAD.

## Routing policy

**Finger inter-column bridges remain mechanically unqualified.** The chassis requires predominantly Y-axis rotation, involving twisting of the long bridge legs that the existing scalar length formulas do not evaluate. See [finger bridge review](docs/finger-bridge-review.md) for the measured rotations, the short index bridge explanation and the missing validation.

Use the deterministic template build as the accepted baseline. Copper and placement are reproducible; native KiCad UUIDs and serialization order can differ between builds, so compare geometry and reports rather than raw file hashes. The finger topology still uses selected legacy BAML routing primitives; v4 stages and modifies a copy, with guarded overrides. This is a migration to a replaceable router interface, not a claim that all legacy routing has been discarded.

Finger boards use the matrix-only seed routing, checked against the native footprints and protected bend regions. Flat thumb clusters use deterministic routing with three vias each. The pod uses the matrix seed. Freerouting is optional regeneration tooling.

```sh
# Optional, networked tool installation. Pinned hashes are checked.
# This bundled runtime is macOS Apple Silicon; other platforms may set
# FREEROUTING_JAVA to their Java 25 executable.
python3 tools/setup_router.py
make benchmark  # experimental finger candidate; failure is not an accepted build
```

### Worker limits and cleanup

Both `./run` and direct `tools/build_thumbs.py` invocations use a
supervisor that starts before the native KiCad libraries load. Only one build
or routing worker can run per checkout. Workers run at reduced CPU priority;
this is not a hard CPU-percentage cap.

Default limits, optionally overridden in `config.json` under `router`:

| Setting | Default |
|---|---:|
| `job_timeout_seconds` | 900 seconds for the entire invocation |
| `completion_timeout_seconds` | 300 seconds per local completion stage |
| `no_progress_seconds` | 120 seconds without a better connectivity/cleanup result |
| `no_progress_iterations` | 25 iterations without a better result |

Individual native DRC calls also have a 60-second timeout. Existing Freerouting
calls retain their configured timeout. Rip-up cycles do not reset the best
result used by the progress checks. A timeout, worker failure, or supervisor
interrupt terminates its process group, including remaining child processes;
children that ignore termination are killed after a two-second grace period.
The supervisor never restarts failed jobs automatically.

`output/native-job-status.json` records the latest supervised job's outcome.
Saved routing checkpoints remain available for inspection; a stopped job does
not make them accepted boards. The overall deadline is enforced from another
process, so a blocked native call cannot bypass it. Keep jobs stopped while
investigating a crash; the safeguards do not fix KiCad's native binding bugs.

Router candidates go to `output/optimized`, preserving the baseline. The router runs locally, with analytics and its API server disabled. `routes/*.json` contain reviewable copper from validated runs, guarded by fingerprints of pad placement, footprint cutouts and routing rules. A changed placement requires rerouting, DRC review and explicit recapture using `rosebear.route_cache.capture`; builds never silently rewrite that source artifact. `--mode fresh` is an experimental finger routing input, not a manufacturing output.

DRC refills and saves zones. Every unconnected item or unexpected violation fails the build. Only the two inherited pod `SW_SPST_SKQG_WithoutStem` library-mismatch warnings for SW1/SW2 are accepted and retained in reports. No schematic parity check is available: the independent electrical contract checks supplement board connectivity DRC.

## Pod pin map

[`pod.json`](pod.json) is the only hand-edited pin map. It holds the WT9932P4-TINY header order, what each costly pin gives up (SD domain, UART0, JTAG, strapping), and the hand-chosen `fixed` group (`rgb`). The seed assigns matrix and button pins from what remains and never takes a fixed group's GPIO, whether or not that group is built. `rosebear/pod_pins.py` stages these into the legacy seed, checks the built pod against them, and writes the generated maps listed above.

To move or add a hand-chosen pin, edit `pod.json` and rebuild. Don't edit pin numbers anywhere else.

## Mechanical verification boundary

The thumb switch frames are coplanar by construction. Conservative checks cover board bounds. They do not establish fit in the old case. The generated plate and alignment spacer are physical fit coupons; final retention and a new complete chassis remain to be designed after the fit trial.

Finger bridges remain unqualified; the [transverse coupon and beam screen](docs/finger-bend-coupon.md) are a construction experiment, not a released replacement.

## Source map

- `rosebear/mechanical.py`: chassis transform export and developed well parameters.
- `rosebear/seed.py`, `seed/`: isolated legacy geometry/templates adapter with cache invalidation.
- `rosebear/pcb.py`: native footprint placement, solder pads, local routing, DRC.
- `rosebear/routing.py`, `route_cache.py`: optional autorouter and deterministic copper replay.
- `rosebear/assembly.py`: transformed assembly and harness.
- `rosebear/validate.py`, `thumb_checks.py`: electrical contracts and protected-flex checks.
- `thumb_geometry.py`, `thumb_mechanical.py`: finite-radius pattern and folded clearance model.
- `flat_thumb.py`, `flat_thumb.json`: current shared thumb layout, routing and printable fit geometry.
- `thumb_artifacts.py`, `finger_artifacts.py`: manufacturing review exports.
